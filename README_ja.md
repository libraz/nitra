# nitra

撮影済みの写真に、美顔カメラ相当の加工を後から掛ける。画像は端末から出ません。

[![License](https://img.shields.io/badge/license-AGPL--3.0%20%2F%20Commercial-green)](https://github.com/libraz/nitra/blob/main/LICENSE)
[![TypeScript](https://img.shields.io/badge/TypeScript-7-3178c6?logo=typescript&logoColor=white)](https://www.typescriptlang.org/)
[![React](https://img.shields.io/badge/React-19-61dafb?logo=react&logoColor=white)](https://react.dev/)

スマートフォンの美顔カメラは、シャッターが開いている間に加工を掛けます。nitra は同じ種類の加工を後から、手元にある任意の写真に掛けます。モードを切り替え忘れた一枚も、他人に撮ってもらった一枚も対象です。

後追いで処理するので、フレームレートの制約がありません。重いパスを必要なだけ掛けられますし、値はいつでも戻せます。

## いまできること

- JPEG・PNG・WebP・AVIF・HEIC を開けます。HEIC をネイティブに読めるのは Safari だけなので、libheif をブラウザ内で使います。
- すべてをリニア Display-P3 に変換し、中間バッファは 16bit/ch で通します。iPhone の写真は広色域で記録されていて、読み込み時に sRGB へ落とすとそこで失われます。
- 階調: 露出、コントラスト、ハイライトとシャドウの復元、白レベルと黒レベル、ホワイトバランス、自然な彩度と彩度、トーンカーブ。
- 彩度は OkLch の chroma として伸縮し、肌の色相域ではゲインを減衰させます。HSV の saturation を定数倍すると色相が転び、肌がいちばん先に飽和します。
- 色別に、色相・彩度・輝度を動かせます。8 つの色域の中心は原色から算出していて、手で書き写してはいません。無彩色に近い画素には掛かりません。曇り空の色相は計算上の値にすぎないからです。
- 効果: スプリットトーン、チャンネル比率つきのモノクロ、フェード、周辺光量、グロー、シャープ、明瞭度、グレイン、ハイライトのロールオフ、8bit へ落とす際のディザ。
- 構図: 反転、90 度回転、角度補正、縦横比を固定できるトリミング。角度を変えても四隅が空かないよう、枠を内側へ詰めます。
- 投稿先が実際に使うサイズに合わせて切り抜けます。Instagram・X・Facebook・YouTube・TikTok。縦横比と画素数を一度に決めます。
- 文字を入れられます。組版はブラウザに任せているので日本語も正しく組め、出力変換のあとで合成しています。文字はその場にあった光ではないからです。
- 手元のどの書体でも組めます。フォントファイルを読み込むとその書体自身で組んだ見本つきで一覧に並びます。文字の中にその書体が持たない字があれば、書き出したファイルを開くまで気付かない代わりに、その場で知らせます。
- 1 枚の写真をグリッド状の複数投稿に分割できます。投稿すべき順番つきです（後述）。
- 画像そのものから初期値を提案します。仕上がりの候補は名前ではなく、自分の写真のサムネイルで選びます。
- 結果を実測して表示します。白飛び、黒つぶれ、彩度クリップ。禁止はしません。
- メタデータは、削除・引き継ぎ・項目ごとの書き込みから選べます。位置情報、撮影日時、カメラ、クレジット（後述）。
- ライトとダーク、英語と日本語で使えます。

顔解析・肌処理・背景ぼけは次の段階です。パイプラインは受け入れられる形にしてありますが、この版には入っていません。

## グリッド分割

プロフィールのグリッドは新しい投稿から埋まります。最後に投稿したものが左上に来るので、9 分割した写真は右下のタイルから順に上げることになります。逆に上げてしまったことに気付くのは、投稿が公開されたあとです。

nitra はその順番を計算して、ファイル名の先頭に書き込みます。番号どおりに上げるだけで組み上がります。タイルは ZIP 1 つにまとめて書き出します。

切り分けるのは描画したあとです。1 枚の完成画像を切っているので、グレインも周辺光量も階調も、継ぎ目をまたいで一致します。タイルごとに描画すると、周辺光量が写真ではなくタイルの中心に掛かります。

## メタデータ

顔写真はこれから SNS に上がる素材で、GPS タグに入った自宅の座標を一緒に持っていく必要はありません。削除が既定で、設定画面の奥ではなく最初の画面に出しています。書き出したバイト列に対してテストで検証しています。何も触っていない編集も同じ動作です。メタデータについて何も言っていないレシピは、メタデータのないファイルを書き出します。

| 項目 | 扱い |
| --- | --- |
| GPS 座標・標高・方位 | 削除 |
| 撮影日時・デジタル化日時 | 削除 |
| カメラとレンズの機種名 | 削除 |
| 本体シリアル番号 | 削除 |
| 埋め込みサムネイル | 削除 |
| 作者・著作権フィールド | 削除 |
| ICC 色プロファイル | **保持** — 除くと表示側で色が破綻します |
| Orientation | 画素に適用してから破棄 |

ブラウザの canvas エンコーダは EXIF を引き継がないので、この工程がなくても書き出しは結果的に綺麗です。だからこそ明示的に実行しています。いまの安全は副作用にすぎず、エンコーダを差し替えた日に、何も壊れないまま失われるからです。

情報のほうが目的になることもあるので、残りの 2 つも用意しています。**引き継ぐ**は元写真が持っていた値を書き戻します。**書き込む**は項目ごとに組み立てます。座標、撮影日時、カメラとレンズ、露出、撮影者と著作権表示。座標は地図がクリップボードに置く形のまま貼り付けられます。2 つの欄に分けて打ち込む必要はありません。

どの場合も、ファイルに入るのはパネルに並んでいる項目そのものです。元のメタデータはそれらの欄に読み込んだ時点で捨てていて、素通しはしません。だから埋め込みサムネイルが書き出しに紛れ込むことがなく、見せていないタグがファイルに入ることもありません。削除は先に走るので、入っているものは入れると決めたものだけです。

英数字以外の文字は、読み取り側が期待する 2 種類の符号化で書き込みます。メタデータを入れられるのは JPEG と PNG で、この版では WebP に入れられません。黙って落とすのではなく、その旨をパネルに出します。**書き込む**状態の編集内容は座標を含むので、その状態でレシピを共有すると座標も渡ります。これもパネルに書いてあります。

## 非破壊編集

元画像は変更しません。編集内容は JSON のレシピで、表示のたびにそこから描画しています。

レシピの量はすべて相対値です。半径は画像サイズに対する比率、座標は正規化した値、文字の大きさは枠に対する比率です。絶対ピクセルで持つと、同じレシピを別の写真に当てた瞬間に意味が変わります。ここを最初に決めておくかどうかで、バッチ適用とプリセット共有が後から入るか入らないかが決まります。文字が、4000px の書き出しでも 9 分割のタイル 1 枚でも同じ位置に収まるのも同じ理由です。

書き出しで引き伸ばすことはありません。投稿先から取った画素数は上限であって目標ではないので、それに届かない写真はそのままのサイズで書き出し、パネルにもその値を出します。プリセットに合わせるために画素を作ると、実際には持っていない解像度を名乗るファイルができます。

レシピは画像を含みません。写真を端末に置いたまま、レシピだけを共有できます。

## 動かす

```bash
bun install
bun run dev
```

WebGL2 と half-float のレンダーターゲットに対応したブラウザが必要です。Chrome・Edge・Safari・Firefox の最新版で動きます。

```bash
bun run check      # lint とフォーマット
bun run typecheck
bun run test
bun run build
```

## 言語

英語と日本語で表示し、ブラウザの設定から選びます。言語を足すときは `src/i18n/locales/` にファイルを 1 つ置き、ロケール一覧に登録するだけです。カタログは英語版に対して型付けしてあるので、未翻訳のメッセージがあるとコンパイルが通りません。

## ライトとダーク

どちらも使えます。「システムに合わせる」は、最初のクリックで上書きされる初期値ではなく独立した選択肢です。写真の編集は昼にも夜にも始まります。

写真のすぐ周りだけは、どちらの外観でも中間グレーのままにしています。色は隣にあるものとの対比で判断するもので、白い背景に置くとどの写真も実際より暗く、暖かく見えます。明るくなるのはその外側だけです。

## 非目標

- **別人化しません。** 骨格の作り替えや顔の入れ替えは扱いません。これは技術的な限界ではなくプロダクトの決定で、後から引き直すより先に決めておくほうが楽です。
- **サーバーを持ちません。** アップロード経路はなく、今後も作りません。
- **アカウント機能を持ちません。** 保存も共有もファイルで完結します。
- 動画は当面スコープ外です。パイプラインは後から拡張できる形にしてあります。
